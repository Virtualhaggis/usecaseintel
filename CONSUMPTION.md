# Consuming Clankerusecase content in your SOC

Everything the pipeline produces is MIT-licensed (code **and** detection
content) and refreshed every ~2 hours. This page is the quick-start for
getting it into your tooling instead of copy-pasting from the website.

> **Honesty first:** queries are schema/syntax-validated (Defender and
> Sentinel KQL through a real Kusto grammar parser; SPL, Sigma, CWLI
> through structural checks), **not executed against live telemetry**.
> Treat everything as a strong starting point: test in staging, tune the
> allowlists, then promote. Details: <https://clankerusecase.com/about.html>

## Splunk

Saved searches for all catalogue use cases, CIM-conformant, disabled by default:

```
rule_packs/splunk/savedsearches.conf
```

Drop into your app's `local/` folder, review, enable per environment.
There is also an IOC lookup CSV updated every run:

```
| inputlookup append=t clanker_iocs.csv
```

Download: <https://clankerusecase.com/intel/splunk_lookup_iocs.csv>

## Microsoft Sentinel

Deployable ARM templates (one analytics rule each, disabled by default):

```bash
az deployment group create \
  --resource-group <rg> \
  --template-file rule_packs/sentinel/<UC_ID>.json
```

## Sigma (route to Elastic, QRadar, anything)

```bash
pip install sigma-cli
sigma convert -t lucene -p ecs_windows rule_packs/sigma/*.yml   # Elastic
sigma convert -t splunk rule_packs/sigma/*.yml                  # Splunk
```

Elastic-native rules are intentionally not exported yet (a previous
version shipped placeholder stubs — worse than nothing). Sigma → ECS is
the supported path until the proper KQL→EQL port lands.

## IOC feeds (no registration, machine-readable)

| Format | URL |
|---|---|
| CSV | https://clankerusecase.com/intel/iocs.csv |
| JSON (with article context) | https://clankerusecase.com/intel/iocs.json |
| STIX 2.1 bundle (MISP / OpenCTI / TIP import) | https://clankerusecase.com/intel/iocs.stix.json |
| RSS | https://clankerusecase.com/intel/iocs.rss.xml |

All IOC values are extracted from defanged source material only — see
`intel/README.md` for extraction-quality guarantees and import examples
(MISP, OpenCTI, Defender TI, Sentinel).

## Use-case catalogue (JSON)

```
https://clankerusecase.com/catalog/use_cases.json
```

Carries `schema_version` (currently `1.0`) — pin your parser to it; any
breaking field change bumps the version. Fields per UC: id, title,
kill_chain, tier, confidence, fp_rate_estimate, mitre_attack[],
data_models[], splunk_spl, defender_kql. Full per-UC detail (all seven
platforms + FP guidance) lives in `catalog/use_cases_full.json`.

## Or just clone it

```bash
git clone https://github.com/Virtualhaggis/usecaseintel.git
```

`use_cases/*.yml` (curated catalogue), `briefings/` (per-article hunt
briefs), `rule_packs/`, `sigma_rules/`, `intel/` — all in the repo, all
regenerated by the scheduled pipeline.
