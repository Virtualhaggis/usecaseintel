Crossplane package installed by mutable tag instead of immutable digest AIInstallation High
Hunts Kubernetes API audit logs for pkg.crossplane.io Provider/Configuration/Function installs whose spec.package references a version tag rather than an @sha256 digest. This is the exact precondition GHSA-wfqx-gjrf-g28r requires: when a package is pulled by tag, a malicious/compromised OCI registry can serve a correctly-signed image for cosign verification and then swap in unsigned content for the actual pull. Rationale: Built directly on the advisory's stated exploit precondition #2 ('Install packages using tag references rather than digests'). The detection keys on the real Crossplane API (pkg.crossplane.io Provider/Configuration/Function, spec.package) and the digest sentinel '@sha256:' that the fix mandates; absence of the digest is exactly what makes an install TOCTOU-exposed. Corroborated against the GHSA, the GitLab advisory mirror, and Crossplane's ImageConfig/package docs. Crossplane ImageConfig signature-verification policy deleted or weakened AIInstallation Medium
Alerts on delete/update/patch operations against imageconfigs.pkg.crossplane.io in the Kubernetes audit stream. Crossplane enforces cosign signature verification only for images matched by an ImageConfig (spec.verification.cosign); removing or editing that resource silently disables verification, the defense the GHSA-wfqx-gjrf-g28r TOCTOU already partially undermines. Surfaces whether the post-change object still carries a verification block. Rationale: Grounded in the advisory's statement that 'package signature verification [is] configured via the ImageConfig mechanism' and Crossplane docs confirming the real resource (imageconfigs.pkg.crossplane.io, spec.verification.cosign). Detects the defense-evasion precursor — tearing down or weakening the cosign policy — using only verifiable API/resource names (no skipSignatureVerification field exists in the schema, so that reviewer suggestion was dropped as ungrounded).
