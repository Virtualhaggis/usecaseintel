EC2 instance IMDS credential theft via curl/wget to security-credentials path AIExploitation Medium
Hunts a shell tool (curl/wget/python) reading IAM role credentials from the EC2 metadata endpoint 169.254.169.254/latest/meta-data/iam/security-credentials/, the exact command the Capital One attacker used to lift the WAF-Role credentials after gaining shell on the instance. Distinguishes interactive credential theft from normal SDK metadata calls by requiring a command-line HTTP tool. Rationale: Anchored on the exact IMDS path string the article shows (curl http://169.254.169.254/latest/meta-data/iam/security-credentials/) plus the requirement that a shell HTTP tool — not the AWS SDK — made the call, which is the differentiator between theft and normal metadata polling. Cross-checked Krebs, AppSecco and AWS re:Post confirming IMDSv1 + curl was the credential-lift vector. Cross-checked against: • https://krebsonsecurity.com/2019/08/what-we-can-learn-from-the-capital-one-hack/ • https://blog.appsecco.com/an-ssrf-privileged-aws-keys-and-the-capital-one-breach-4c3c2cded3af • https://repost.aws/knowledge-center/resolve-guardduty-credential-alerts

WAF-Role EC2 instance credentials used from external IP (instance credential exfiltration) AIActions on Objectives High
Hunts CloudTrail AssumedRole activity for the instance role (WAF-Role) appearing from more than one distinct source IP, the signature of EC2 role credentials stolen via IMDS and replayed from outside AWS (the Capital One attacker used Tor/IPredator exit IPs). This is the GuardDuty InstanceCredentialExfiltration.OutsideAWS / TorIPCaller scenario expressed on raw CloudTrail. Rationale: Uses the article's named role (WAF-Role) and the structural invariant that a legitimate instance-role session is exercised only from its own instance IP — a second source IP on the same session ARN is the exfiltration tell. Corroborated by AWS GuardDuty docs (InstanceCredentialExfiltration.OutsideAWS) and the FBI-complaint detail that the attacker reached AWS via Tor exit nodes. Cross-checked against: • https://repost.aws/knowledge-center/resolve-guardduty-credential-alerts • https://aws.amazon.com/about-aws/whats-new/2022/01/amazon-guardduty-ec2-instance-credentials-aws-account/ • https://krebsonsecurity.com/2019/08/what-we-can-learn-from-the-capital-one-hack/

WAF-Role mass S3 bucket enumeration and object download AIActions on Objectives High
Hunts the stolen WAF-Role session performing ListBuckets followed by GetObject/ListObjects across an abnormally large number of distinct buckets — the Capital One actor's enumeration and duplication of 700+ buckets. Targets the data-plane fan-out that distinguishes bulk exfiltration from normal application access to a handful of buckets. Rationale: Anchored on the article's named WAF-Role plus the FBI-complaint detail of 700+ buckets enumerated/duplicated; the detection keys on distinct-bucket fan-out (threshold 50, far below 700 to catch earlier-stage activity) rather than raw object count, which is the cloud-storage-exfil invariant. Second-sourced via Krebs and AppSecco describing the ListBuckets→GetObject bulk pull.
