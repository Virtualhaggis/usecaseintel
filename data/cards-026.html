Celery worker (Python) spawning a shell — CVE-2021-23727 stored command injection AIExploitation Medium
Hunts the post-exploitation footprint of CVE-2021-23727: a Celery worker (Python process whose command line contains 'celery') spawning /bin/sh or another shell/recon binary. The vuln's exception_to_python path resolves exc_module/exc_type (e.g. os.system) and calls it with exc_message, so successful exploitation surfaces as a celery-parented Python process executing OS commands it normally never runs. Rationale: Anchors on the article's concrete exploit shape: exc_module='os'/exc_type='system' makes the celery worker (python) call os.system, which fork/execs /bin/sh -c <exc_message>. Celery workers almost never spawn interactive shells, so a celery-parented Python → shell tree is high-fidelity. Cross-checked the patched version (5.2.2) and exploit mechanics against GHSA-q4xr-rc97-m4xx and Red Hat Bugzilla 2037531. Cross-checked against: • https://github.com/advisories/GHSA-q4xr-rc97-m4xx • https://bugzilla.redhat.com/show_bug.cgi?id=2037531 • https://security.snyk.io/vuln/SNYK-PYTHON-CELERY-2314953

Contain: isolate the affected worker host and quarantine/flush the result backend entries that carried the tainted exception payload; rotate backend credentials if exposed. 3. Hunt: search all celery workers for the same parent→shell pattern, check for follow-on egress from the worker, and confirm Celery version — anything <5.2.2 is exploitable; prioritize patching.

Phishing-link click correlated to endpoint execution Delivery High
User received an external email containing a URL, clicked it, and within 60 seconds the recipient's endpoint spawned a scripting interpreter or network downloader (PowerShell / cmd / mshta / curl / certutil / bitsadmin). This is the high-fidelity shape — a raw "user clicked an emailed URL" query is too noisy to alert on because every Microsoft 365 tenant generates thousands of legitimate clicks per day.
