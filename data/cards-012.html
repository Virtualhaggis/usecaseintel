Phishing-link click correlated to endpoint execution Delivery High
User received an external email containing a URL, clicked it, and within 60 seconds the recipient's endpoint spawned a scripting interpreter or network downloader (PowerShell / cmd / mshta / curl / certutil / bitsadmin). This is the high-fidelity shape — a raw "user clicked an emailed URL" query is too noisy to alert on because every Microsoft 365 tenant generates thousands of legitimate clicks per day. The exec-correlation step suppresses the noise to roughly the rate at which a click actually drives onto-host execution, which is the actionable signal.         | where DeliveryAction == "Delivered"
        | where EmailDirection == "Inbound"
        | project NetworkMessageId, Subject, SenderFromAddress, SenderFromDomain,
                  RecipientEmailAddress, EmailTimestamp = Timestamp
      ) on NetworkMessageId
    | join kind=leftouter (
        EmailUrlInfo | project NetworkMessageId, Url, UrlDomain
      ) on NetworkMessageId, Url
    | project ClickTime = Timestamp, AccountUpn, IPAddress, Url, UrlDomain,

              ActionType;

[LLM] Next.js CVE-2025-29927 middleware bypass via x-middleware-subrequest header Exploitation High
Hunts inbound HTTP requests carrying the literal header `x-middleware-subrequest: middleware` against self-hosted Next.js apps. This header is the documented bypass primitive for CVE-2025-29927 — no legitimate external client ever sets it, because it is an internal-only Next.js signal designed to avoid recursive middleware invocation. Any external occurrence is exploitation or recon. Rationale: Detection anchors on the exact header string named in the article and Vercel advisory — `x-middleware-subrequest`. The article's Block 2 verbatim shows `x-middleware-subrequest: middleware`. This header is an internal Next.js framework signal that should never appear in inbound traffic from external clients, making any external occurrence an exploitation attempt. Cross-checked with the Vercel security advisory at https://github.com/vercel/next.js/security/advisories/GHSA-f82v-jwr5-mffw and the GHSA entry which confirm the header is the specific bypass primitive and that version-specific value variants exist (the `has` operator catches them all).
