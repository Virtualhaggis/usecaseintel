[LLM] Runner.Worker process memory dumped via /proc/PID/mem read on Linux runner Actions on Objectives High
Detects the credential-access primitive of CVE-2025-30066: a python process opening /proc/<pid>/maps and /proc/<pid>/mem of the GitHub Actions Runner.Worker to scrape plaintext secrets. Hunts the exact technique memdump.py uses, not the script name. Rationale: The article's reproduced memdump.py opens /proc/<pid>/maps and /proc/<pid>/mem after finding the pid of 'Runner.Worker'. Reads of /proc/PID/mem by python (not gdb/strace/criu) are exceptionally rare in normal CI/CD operation, so a process-creation join with the /proc/PID/mem open is a high-fidelity, attack-specific signal that survives the script being renamed. Verified against Wiz and Sysdig analyses that both call out this primitive.
